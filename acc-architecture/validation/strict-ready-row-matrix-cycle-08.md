# Cycle 08 — مصفوفة موانع strict-ready على مستوى المتطلب

**Baseline:** `507c7523de96818da30b2d4c2abcab23d0e86b0a`

**الحكم:** أصبح بالإمكان تتبع كل علامة strict-ready إلى صف المتطلب، وحقول المصدر، وفئاته الأخرى. هذه إضافة تشخيصية؛ لا تحسم فجوة أو قراراً ولا تغيّر الجاهزية.

## كيف نقرأ رقم 871؟

الـ**871** هو مجموع فئات strict-ready المسجلة على **268 صفاً نشطاً**، وليس 871 متطلباً ولا 871 سبباً جذرياً مستقلاً. تعيد المصفوفة الرقم بجمع فئة واحدة كحد أقصى من كل نوع لكل صف:

| الفئة المسجلة | صفوف متأثرة |
|---|---:|
| حالة دورة الحياة ليست `ACCEPTED` | 268 |
| مرجع Use Case/function يحتوي placeholder غير محسوم | 180 |
| توجد مراجع في `open_decisions` | 200 |
| التحقق لا يزال مخططاً | 223 |
| **المجموع الحسابي للفئات المتداخلة** | **871** |

وتعرض الدورة ثمانية أشياء مختلفة لا ينبغي الخلط بينها: الـ200 صفاً التي تحمل قراراً مفتوحاً، و393 علاقة صف–مرجع موزعة على 61 مرجعاً؛ و180 علاقة صف–RGAP موزعة على 11 فجوة. أما التحقق المخطط فيخص 223 صفاً وله 209 نصوص مراجع مختلفة.

## أنماط التداخل السبعة

كل صف نشط يحمل فئة الحالة، وتظهر هذه التركيبات المسجلة:

| فئات strict-ready على الصف | عدد الصفوف |
|---|---:|
| الحالة + Use Case + قرار + تحقق مخطط | 99 |
| الحالة + قرار + تحقق مخطط | 57 |
| الحالة + Use Case + تحقق مخطط | 50 |
| الحالة + Use Case + قرار | 30 |
| الحالة + تحقق مخطط | 17 |
| الحالة + قرار | 14 |
| الحالة + Use Case | 1 |
| **المجموع** | **268** |

هذا تصنيف للتداخل كما يطبقه المدقق الحالي، وليس تقديراً للأهمية أو ترتيباً للأولوية أو دليلاً على أن صفاً بعينه «سهل» الإغلاق.

## المصفوفة العكسية

ملف [`strict-ready-row-matrix-cycle-08.csv`](strict-ready-row-matrix-cycle-08.csv) يحوي **صفاً واحداً لكل متطلب نشط عليه مانع**. يضم معرّف المتطلب ومستواه ومرحلته وملف الوثيقة والعنوان والنص والحالة ومعايير القبول، ثم أسماء الفئات وعددها لهذا الصف. يساعد `predicate_count` على تدقيق مساهمة الصف في 871، لكنه يعد الفئات فقط لا الأسباب أو مراجع القرار.

تحتفظ المصفوفة بالقيم الخام كما وردت في السجل (`use_case_id_source` و`open_decisions_source` و`planned_verification_source`) بجانب الروابط المفككة. تعرض `use_case_rgap_refs` روابط RGAP الموجودة، وتفصل بين مراجع ADR التي عُثر على سجلها وحالته المسجلة وبين الرموز التي لا تطابق ADR مسجلاً. غياب الحالة عن رمز لا يثبت أنه مغلق أو معتمد.

يُستفاد من المصفوفة مع [`فهرس Cycle 07 التجميعي`](strict-ready-dependency-ledger-cycle-07.csv): المصفوفة تعطي الاتجاه من المتطلب إلى فئاته وحقوله، والفهرس يعطي الاتجاه من مجموعة مرجع إلى المتطلبات المتأثرة. كلاهما مصدره بيانات السجل، ولا يستنتج قبول الأب من الأبناء.

## التوليد والحدود

يولد [`generate_strict_ready_row_matrix.py`](generate_strict_ready_row_matrix.py) المصفوفة من سجل المتطلبات. يتحقق من وجود baseline ومن تطابق ملفي المتطلبات والقرارات معه، ويمرر التحقق البنيوي، ويحصر الكتابة داخل مجلد `validation/`.

```bash
python3 acc-architecture/validation/generate_strict_ready_row_matrix.py \
  --baseline 507c7523de96818da30b2d4c2abcab23d0e86b0a \
  --output acc-architecture/validation/strict-ready-row-matrix-cycle-08.csv
```

تستبعد المصفوفة الصفوف العشرة `RETIRED` من predicates النشطة، لكنها تبقى خاضعة للفحص البنيوي ومتطلبات إثبات التقاعد. في هذه الدورة لم تتغير `requirements-registry.csv` أو `decisions.json` أو حالات الصفوف. لم تُسجل موافقة `ACCEPTED` أو `IMPLEMENTATION_READY`، ولم يُضف PH-05، ولم تُحل فجوة أو قرار بالتخمين. الاختبارات بعد إضافة المصفوفة **28/28 PASS**، والفحص البنيوي يظل **278/278 PASS**؛ strict-ready نفسه يظل **FAIL** بالعدد 871/268.

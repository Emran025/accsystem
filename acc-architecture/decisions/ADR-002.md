# ADR-002 — Independent ACCore Instance per Institution

**Decision ID:** ADR-002  
**Status:** PROPOSED — ARCHITECTURAL DEFAULT; owner ratification not recorded  
**Date:** 2026-11-15  
**Evidence:** idea.md §4.1, §12

---

## 1. Problem / Context

Institutions (universities, companies) need ERP capabilities (product master, inventory, sales, finance, org/users). The question is whether these are hosted in a single shared system or in isolated per-institution instances.

idea.md §4.1 describes ACCore as a per-institution system. §12 leaves the **hosting form** as an open decision (SaaS, self-hosted, or platform-managed).

---

## 2. Alternatives Considered

| Alternative | Description | Trade-offs |
|---|---|---|
| **A — Independent per-institution instance** (selected) | Each institution runs its own ACCore with dedicated DB | + Full data isolation. + Institutions can operate offline/air-gapped. + Independent upgrade cycles. — Operational complexity (N instances). — Unknown hosting form. |
| **B — Multi-tenant shared ACCore** | Single ACCore instance, all institutions in one DB (schema-based isolation) | + Simpler operations. — Data breach risk (one instance affects all). — Cannot operate offline independently. — Contradicts idea.md §4.1. |
| **C — Shared SaaS with logical isolation** | Shared infrastructure, isolated per-tenant schemas | + Lower operational overhead. — Upgrade coupling. — Offline operation impaired. |

---

## 3. Decision

Each institution operates an **independent ACCore instance with its own database**. ACCore handles: product master, inventory, sales, finance, organization & user management.

Hosting form is **UNKNOWN** — this is a critical open decision (idea.md §12). Options include:
- Institution self-hosted
- Platform-managed per-institution SaaS (most likely — ASSUMPTION)
- Hybrid

**Status: PROPOSED** | Hosting form UNKNOWN.

---

## 4. Rationale

- CONFIRMED (idea.md §4.1): "per-institution ACCore" language
- Independent instances enable offline operation (idea.md §12 — open decision)
- Data isolation requirement aligns with institutional data governance needs (ASSUMPTION)

# ADR-007 — Order Domain Coordinates Payment and Delivery Without Owning Their Logic

**Decision ID:** ADR-007  
**Status:** PROPOSED  
**Date:** 2026-11-15  
**Evidence:** idea.md §8, §9, §10

---

## 1. Problem / Context

An order requires payment and (for physical goods) delivery. The question is whether order management owns payment processing and delivery logic, or whether these are owned by separate services that the order domain coordinates.

---

## 2. Alternatives Considered

| Alternative | Description | Trade-offs |
|---|---|---|
| **A — Separate services, coordinated by Orders** (selected) | CNT-ACC-PAYMENT owns payment logic; CNT-ACC-DELIVERY owns delivery logic; CNT-ACC-ORDERS (CMP-ORD-SAGA) coordinates via saga | + High cohesion per service. + Independent scaling and deployability. + Payment provider changes don't affect order logic. — Saga orchestration complexity. |
| **B — Orders owns all logic** | Monolithic order service that includes payment processing and delivery scheduling | + Simpler coordination. — Violates bounded-context separation. — Large, difficult to evolve service. — Provider changes require order service changes. |
| **C — Event-driven only (choreography)** | No saga orchestrator; services react to events | + Loose coupling. — Difficult to track saga state. — Hard to implement compensation. — Not recommended for financial transactions. |

---

## 3. Decision

**CNT-ACC-ORDERS (CMP-ORD-SAGA) is the saga orchestrator.** It coordinates:
- CNT-ACC-PAYMENT: for payment authorization, capture, void, and refund
- CNT-ACC-DELIVERY: for delivery job creation and tracking

It does NOT implement payment provider logic (CMP-PAY-ADAPTER) or delivery route logic (CNT-ACC-DELIVERY internals). The saga orchestrator knows the steps and compensation; it delegates to the domain services for execution.

---

## 4. Rationale

- CONFIRMED (idea.md §8): Orders service coordinates the purchase flow.
- CONFIRMED (idea.md §9): Payment is an independent service integrating with EXT-PAYMENT-PROVIDER.
- CONFIRMED (idea.md §10): Delivery is an independent service.
- Saga orchestration (ADR-013) requires a coordinator; CNT-ACC-ORDERS is the natural owner.

---

## 5. Consequences, Risks, Mitigations

| Consequence | Type | Mitigation |
|---|---|---|
| Saga state machine adds complexity | Development | CMP-ORD-SAGA and CMP-ORD-STATEMACHINE explicitly document all transitions |
| Payment capture timing undefined | UNKNOWN | Capture point (at confirmation vs delivery) is open decision (§12); OWNER_UNASSIGNED |
| Delivery service failure blocks order completion | Availability | Delivery job creation is async post-confirmation; failure retried, does not block order CONFIRMED state |
| Multi-seller delivery coordination | UNKNOWN | Physical vs software products per seller; delivery scope not fully specified |

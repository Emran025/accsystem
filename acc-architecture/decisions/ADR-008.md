# ADR-008 — ACCMared Apps are Client UIs; Delivery Backend Lives in ACCSystem

**Decision ID:** ADR-008  
**Status:** PROPOSED  
**Date:** 2026-11-15  
**Evidence:** idea.md §10, §10.1

---

## 1. Problem / Context

ACCMared Supervisor (Flutter desktop) and ACCMared Courier (mobile) provide delivery management interfaces. The question is whether business logic for delivery management (routing, assignment, tracking) lives in these apps or in a backend service.

---

## 2. Alternatives Considered

| Alternative | Description | Trade-offs |
|---|---|---|
| **A — Thin client UIs, backend in ACCSystem** (selected) | ACCMared apps are interaction clients; CNT-ACC-DELIVERY in ACCSystem owns authoritative delivery state and logic. A local queued update, if enabled, is pending client intent rather than authoritative state. | + Single source of truth. + Logic not duplicated across clients. — Connectivity and offline interaction policy remain explicit operational concerns. |
| **B — Courier app owns delivery state** | Courier mobile app maintains authoritative delivery state | + Works offline. — State conflicts when multiple couriers interact. — Financial/audit state in a mobile app is risky. |
| **C — Separate delivery backend service** | Independent microservice not part of ACCSystem | + Deployment isolation. — Integration complexity. — Another system boundary to manage. |

---

## 3. Decision

**ACCMared Supervisor and ACCMared Courier are frontend clients only.** All delivery business logic (job assignment, state transitions, route management, tracking) resides in CNT-ACC-DELIVERY within ACCSystem.

Clients connect to ACCSystem via CNT-ACC-APIGATEWAY. Courier app submits delivery-status commands via API calls; ACCMared Supervisor reads delivery dashboards from the same API. Only CNT-ACC-DELIVERY validates and commits authoritative delivery-state transitions. A client may display provisional local progress or queue a pending command, but that local record is not a backend state change and must be reconciled against the server result. Whether offline submission is enabled, which operations may queue, local protection/retention, retry/conflict handling, and any duration limits remain UNKNOWN and require the relevant owner approvals. Online-only interaction and conditionally enabled queued interaction are not globally selected by this ADR; it settles backend ownership only.

## 4. Rationale

- CONFIRMED (idea.md §10): ACCMared is described as interface applications.
- CONFIRMED (idea.md §10.1): Delivery state managed centrally.
- Thin-client pattern consistent with ACCSystem as the platform authority.

# ADR-001 — ACCSystem is a Marketplace Platform, Not an ERP

**Decision ID:** ADR-001  
**Status:** PROPOSED  
**Date:** 2026-11-15  
**Evidence:** idea.md §1, §3.1, §4.1, §14

---

## 1. Problem / Context

The ACC ecosystem involves institutional buyers and sellers operating in a multi-system environment. A central design question is whether ACCSystem should absorb ERP functions (inventory, finance, sales records) or remain strictly a marketplace intermediary.

idea.md §1 describes ACCSystem as a "marketplace platform" and §4.1 describes each institution having an independent ACCore ERP system. The fundamental choice is: should ACCSystem embed product, inventory, and financial management, or delegate these to institution-owned systems?

---

## 2. Alternatives Considered

| Alternative | Description | Trade-offs |
|---|---|---|
| **A — Marketplace only** (selected) | ACCSystem stores only marketplace projections. ACCore owns product master, inventory, finance. | + Clear data ownership. + Institution controls its own data. + ACCSystem scales independently. — Integration complexity. — Eventual consistency for catalog. |
| **B — Shared ERP** | ACCSystem hosts a shared ERP for all institutions | + Single data store. + No integration layer. — Data isolation problems. — Institutions cannot run offline. — Does not match idea.md §4.1 model. |
| **C — Hybrid (ACCSystem + embedded mini-ERP)** | ACCSystem embeds lightweight inventory for marketplace items only | + Simpler integration. — Duplicated data. — Conflicts with ACCore as source of truth. — Complicates multi-tenancy. |

---

## 3. Decision

**ACCSystem is a marketplace intermediary.** It stores only the data necessary to operate the marketplace:
- Catalog projections (not product master)
- Order state (not institution sales records)
- Payment coordination (not institution financial records)
- License entitlements (original — no ERP equivalent)

Each institution's ERP functions (product, inventory, finance) reside exclusively in that institution's ACCore instance.

**Status: PROPOSED** — not yet validated with all stakeholders. Revisit trigger: discovery that an institution requires ACCSystem to host its ERP data.

---

## 4. Rationale

- CONFIRMED (idea.md §4.1): ACCore is described as an independent, institution-owned ERP system.
- CONFIRMED (idea.md §3.1): ACCSystem services are marketplace-scoped (Catalog, Orders, Payment, License — none are ERP services).
- Marketplace-only design allows institutions to operate ACCore independently (offline, air-gapped) — a stated requirement (idea.md §12 — open decision on ACCSystem offline behavior).

# ADR-009 — ACManagement is a Frontend Client for Platform Management Services

**Decision ID:** ADR-009  
**Status:** PROPOSED  
**Date:** 2026-11-15  
**Evidence:** idea.md §6, §7

---

## 1. Problem / Context

Platform administrators and support staff need to manage the marketplace: onboard institutions, manage software catalogs, handle licenses, and configure the platform. ACManagement provides this interface. The question is whether ACManagement is a thin client or contains its own backend business logic.

---

## 2. Alternatives Considered

| Alternative | Description | Trade-offs |
|---|---|---|
| **A — Thin client for ACCSystem services** (selected) | ACManagement's public portal and admin console are frontend applications; all business logic in CNT-ACC-SOFTCAT, CNT-ACC-LICENSE, CNT-ACC-PLATFORMADMIN | + Logic lives where it belongs. + ACManagement is replaceable. + Single API surface. — UI depends on ACCSystem APIs. |
| **B — ACManagement has own backend** | ACManagement includes its own API server and business logic | + Self-contained. — Duplicated logic with ACCSystem. — Two sources of truth for platform config. |

---

## 3. Decision

**ACManagement (SYS-ACMANAGEMENT) consists of two frontend applications:**
- **CNT-ACM-PUBLIC**: Public-facing portal for institutions to register, view catalog, manage accounts
- **CNT-ACM-ADMIN**: Internal admin console for platform admins and support staff

Both are thin clients consuming ACCSystem APIs via CNT-ACC-APIGATEWAY. Business logic for platform management resides in CNT-ACC-PLATFORMADMIN, CNT-ACC-SOFTCAT, and CNT-ACC-LICENSE.

---

## 4. Rationale

- CONFIRMED (idea.md §6): ACManagement described as portal/admin interface.
- CONFIRMED (idea.md §7): Software Catalog and License Management are ACCSystem services.
- Thin client = ACManagement can be rebuilt/replaced without touching business logic.

---

## 5. Consequences, Risks, Mitigations

| Consequence | Type | Mitigation |
|---|---|---|
| ACManagement fully depends on ACCSystem API availability | Availability | ACCSystem SLA must cover admin operations |
| Admin console must be secured | Security | ADR-011: least-privilege, approval, audit for admin access |
| Public portal + admin console share same system | Security | Strict RBAC separation; different auth scopes |

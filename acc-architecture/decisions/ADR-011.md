# ADR-011 — Admin and Support Access: Least Privilege, Approval, Scope, and Audit

**Decision ID:** ADR-011  
**Status:** PROPOSED  
**Date:** 2026-11-15  
**Evidence:** idea.md §6, §14

---

## 1. Problem / Context

Platform administrators (ACT-PLATFORM-ADMIN) and support staff (ACT-SUPPORT-STAFF) have elevated access to sensitive platform data and operations. If their access is not constrained, any compromise or misuse could affect all institutions and buyers on the platform.

---

## 2. Alternatives Considered

| Alternative | Description | Trade-offs |
|---|---|---|
| **A — Least privilege + approval + scoped sessions + full audit** (selected) | Admin roles are narrowly scoped; elevated operations require approval; sessions are time-limited; all actions audited | + Defense in depth. + Insider threat mitigation. + Compliance-ready. — More operational overhead. |
| **B — Broad admin role** | Admin users have full access | + Simple. — Single admin compromise → platform-wide breach. — Difficult to audit specific access. |
| **C — Support has read-only access** | Support staff can view but not modify | + Limits damage from support compromise. — Support cannot resolve issues requiring data modification. |

---

## 3. Decision

**All admin and support access follows four principles:**

1. **Least Privilege:** Roles scoped to minimum necessary capabilities. ACT-PLATFORM-ADMIN and ACT-SUPPORT-STAFF roles defined in CNT-ACC-IDENTITY RBAC with explicit permission sets.

2. **Approval for Elevated Operations:** Operations classified as HIGH_RISK (e.g., institution deactivation, bulk data deletion, license revocation) require a second approver (ASSUMPTION — 4-eyes principle; exact approval flow UNKNOWN).

3. **Scoped Sessions:** Admin and buyer session TTLs are separate configurable policy keys owned by Identity/Security Operations; no duration is asserted before security and usability review. Scope is explicitly declared at session creation.

4. **Full Audit:** Every admin and support action is written to CNT-ACC-AUDIT with: actor_id, role, operation, resource_id, timestamp, session_id. Audit log is append-only and tamper-evident (ASSUMPTION).

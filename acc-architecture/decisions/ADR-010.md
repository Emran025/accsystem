# ADR-010 — Software Catalog, License Management, and Identity are Separate Services

**Decision ID:** ADR-010  
**Status:** PROPOSED  
**Date:** 2026-11-15  
**Evidence:** idea.md §3.1, §5, §7

---

## 1. Problem / Context

Platform Management Control Plane encompasses software catalog management, license issuance and enforcement, and identity/access management. The question is whether these are bundled into one service or separated.

---

## 2. Alternatives Considered

| Alternative | Description | Trade-offs |
|---|---|---|
| **A — Separate services** (selected) | CNT-ACC-SOFTCAT, CNT-ACC-LICENSE, CNT-ACC-IDENTITY are independent containers | + Independent scaling and deployability. + Clear bounded contexts. + License changes don't affect identity. — More inter-service calls. |
| **B — Combined Platform Service** | Single platform management service handles catalog, licenses, and identity | + Simpler. — Tight coupling. — License management is complex (ADR-014); deserves isolation. — Identity is cross-cutting; bundling limits reuse. |

---

## 3. Decision

**Three separate services:**
- **CNT-ACC-SOFTCAT**: Software Catalog — manages published software products available for licensing
- **CNT-ACC-LICENSE**: License Management — issuance, entitlement, lifecycle, offline token generation
- **CNT-ACC-IDENTITY**: Identity & Access Management — authentication, RBAC, sessions, tenancy

These services interact via internal APIs and events; they do not share databases.

---

## 4. Rationale

- CONFIRMED (idea.md §3.1): All three listed as distinct modules.
- CONFIRMED (idea.md §5): Identity is explicitly cross-cutting across all systems.
- CONFIRMED (idea.md §7): Software Catalog and License are logically distinct management domains.
- Identity is used by all other services; isolation prevents circular dependencies.

---

## 5. Consequences, Risks, Mitigations

| Consequence | Type | Mitigation |
|---|---|---|
| License activation must call Software Catalog | Service dependency | CMP-LIC-ISSUANCE calls CNT-ACC-SOFTCAT; circuit breaker if unavailable |
| Identity called on every request | Latency | Token validation cached at API Gateway; session store (Redis) |
| Three separate databases to operate | Operational | Shared infrastructure but isolated schemas |

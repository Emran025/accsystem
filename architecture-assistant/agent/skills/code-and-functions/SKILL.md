# Skill: code-and-functions

Purpose: decide whether code views add value, create focused C4/code views when justified, and trace important operations.

## Procedure

For every C3 component, record a C4 view disposition. Create code diagrams only for important/complex components where code is evidenced and the view answers a named question. Keep them within one component and show only code elements that explain the story. For routine components, rapidly changing code, unavailable source, or unclear value, mark not-selected/deferred with reason and revisit trigger. A prose module record or function catalog is not itself a C4 code diagram. Do not invent frameworks, implementation details or signatures. Separately catalog important business operations and map them to stable function IDs; define contracts, pre/postconditions, rules, effects, failures, authorization, observability and tests when useful.

## Required output

Provide evidence/source IDs, created/updated artifact paths, registry changes, gate result, unresolved facts and next-step recommendation.

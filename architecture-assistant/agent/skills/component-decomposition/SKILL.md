# Skill: component-decomposition

Purpose: produce complete, evidence-based C3 coverage decisions and focused diagrams for selected containers.

## Procedure

Iterate over every in-scope software container ID. Create a disposition row for each. Select detailed C3 work where complexity, business criticality, security/regulatory boundaries, change coupling, uncertainty, ownership or implementation planning create clear value. For each selected container, enumerate meaningful components within declared scope and document responsibility, boundaries, interfaces, collaborators, data, rules, flows, failures, security and transactions; create a focused diagram when useful. For non-selected/deferred containers, state why, what remains unknown, revisit trigger, priority, owner and planned phase. Do not use a representative sample while claiming full decomposition. Keep registries/inventories complete when drawings are selective. Follow `policies/diagram-selection-policy.md`.

## Required output

Provide evidence/source IDs, created/updated artifact paths, registry changes, gate result, unresolved facts and next-step recommendation.

# Skill: container-decomposition

Purpose: build complete C2 inventories and decision-useful decomposition plans for large systems.

## Procedure

Identify every known application/service/data store, owner, responsibility, boundary, interface/protocol, data ownership, dependency, security/operation/failure concern and technology status. Separate external systems from internal containers. Map capabilities and evidence. For each container, decide whether C3 adds value using complexity, criticality, uncertainty, change coupling, security boundary, ownership and implementation need. Selected containers are decomposed meaningfully and completely within stated scope. Otherwise record rationale, evidence gaps, priority, revisit trigger and owner; do not call a phased analysis complete. Follow the microservices decision policy; do not translate every container into a service or assume architecture style.

## Required output

Provide evidence/source IDs, created/updated artifact paths, registry changes, gate result, unresolved facts and next-step recommendation.

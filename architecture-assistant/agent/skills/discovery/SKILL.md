# Skill: discovery

Purpose: inspect the project before architecture claims.

## Procedure

Read repository instructions, requirements, code manifests, existing diagrams and ADRs. Use scoped RAG over relevant project folders; cite file path/chunk and distinguish direct evidence from inference. Inventory systems, domains/capabilities, repositories, teams/owners, deployments/environments, integrations, data stores, technologies, constraints, risks and unknowns. Screen analysis scale from evidence about system/team relationships, domain breadth, change coupling, deployment topology, critical workflows, risk and operations; do not use arbitrary item-count cutoffs. For a huge scope, propose layered portfolio→system→domain→container analysis with stable IDs, complete/partial/deferred status, owners and follow-up. Avoid flattening the estate into one unreadable diagram. Do not fabricate behavior or begin C1 before scope evidence is adequate.

## Required output

Provide evidence/source IDs, created/updated artifact paths, registry changes, gate result, unresolved facts and next-step recommendation.

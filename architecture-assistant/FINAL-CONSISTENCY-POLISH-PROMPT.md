```text

First read the current consistency ledger, registries, requirements, ADRs, open issues, diagram plan, diagram-coverage matrix, stage manifest, and all relevant saved artifacts. Then reopen and reread every changed file and all impacted dependents from disk, rerun `validate_architecture.py`, `validate_artifact_depth.py`, `validate_consistency_artifacts.py`, reference/traceability/diagram-ID checks, and recheck each finding from both directions. Repeat until a complete pass finds no new material inconsistency. If limits prevent that, checkpoint the exact remaining findings and mark the gate PARTIAL or BLOCKED—never imply it passed.

Update the consistency ledger, diagram-coverage matrix, consistency report, manifest, and checkpoint so they agree. Report what was checked, exact evidence and tool limits, unresolved conflicts, unverified syntax/render/visual/security checks, and the precise resumption point. A clean pass is limited to the declared scope and does not certify semantic correctness, production readiness, or discovery of unknown requirements.
```

## Final diagram artifact acceptance
Treat actual diagram source/render files as release deliverables. Confirm at least one current saved diagram was produced/refreshed at each workflow stage and that each stage's checkpoint names it. Confirm the final package contains the actual C1/C2 baseline views per focal system, every selected deeper/supporting view, plus an index and cross-linked partitions for large scopes. A diagram plan or coverage matrix alone fails acceptance. Recheck all final diagram files against current IDs, relationships, scope, evidence and consistency findings; run syntax/parser, render and visual checks separately when possible, and record exact results. If a selected view is absent or a check was unavailable, do not report a clean diagram gate; state NOT_VERIFIED/BLOCKED with the exact next action. Preserve C4's evidence-based selection rule—do not create C3/C4 or supporting views mechanically just to populate a list.

## Release status coherence check
Run `scripts/validate_release_status.py` only after regenerating the current structural, depth, traceability, diagram-coverage and consistency reports. Compare its output with the actual manifest and validation reports. A declared PASSED release must be rejected if any BLOCKER/MAJOR finding, incomplete required stage, missing canonical ledger/matrix/review report or blocked validation report remains. A coherent BLOCKED result must remain BLOCKED; do not edit findings or statuses merely to obtain a clean exit. Re-open the audit after every repair and record the exact result.

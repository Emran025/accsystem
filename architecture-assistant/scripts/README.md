# Validation scripts

Run structural checks from any directory: `python3 /path/to/architecture-assistant/scripts/validate_architecture.py /path/to/architecture`. Writes `validation/coverage-report.md` and `validation/traceability-report.md`; exit code 0 means registry/reference checks passed, not semantic or visual certification. Coverage separates complete decomposition states, exceptions, unresolved items and missing IDs; exceptions are not counted as completed deliverables. The validator rejects assistant/model self-approval and contradictory Gate 7 status.

Run the heuristic outline audit: `python3 /path/to/architecture-assistant/scripts/validate_artifact_depth.py /path/to/architecture`. It checks registered C2/C3/C4/function/interface/decision files for family-specific topic groups and common template placeholders; writes `validation/depth-review-report.md`; exit code 1 means the outline is incomplete or registry paths failed. It does not determine whether content is true, sufficient or consistent—manual expert review remains mandatory.

Run `python3 /path/to/architecture-assistant/scripts/validate_consistency_artifacts.py /path/to/architecture` to check that the consistency ledger, diagram matrix and review report exist and that every in-scope registry ID has a matrix row with a diagram reference/path or explicit disposition. Referenced local diagram files must exist within the project; an obvious `PASSED` report with open BLOCKER/MAJOR rows is rejected. Writes `validation/consistency-artifact-validation.md`. This is a structural presence/coverage check, not a semantic diagram or contradiction detector. `validate_traceability.py`, `validate_references.py`, `generate_coverage_report.py`, and `validate_diagrams.py` provide focused invocations. The diagram validator checks registered IDs and, when `mmdc` is available on `PATH`, renders every fenced Mermaid block. If the renderer is missing it returns `NOT_VERIFIED` (exit 2); PASS means registry-ID checks and renderer/parser acceptance only, not semantic correctness, C4 completeness, or owner approval. Follow the full iterative audit in `CONSISTENCY-AND-POLISH-POLICY.md`.

## Release status coherence audit
Run `python3 /path/to/architecture-assistant/scripts/validate_release_status.py /path/to/architecture`. This checks whether the Gate 7 row and `registry/architecture-manifest.json` agree, whether a declared release PASS conflicts with explicit BLOCKER/MAJOR findings or blocked depth/consistency reports, and whether release PASS has its canonical ledger, diagram matrix and consistency review report. It writes `validation/release-status-audit.md`. Exit code 0 means only that the status records are internally consistent under these checks; a coherent `BLOCKED` release is allowed. Exit code 1 means contradictory status records or missing prerequisites for a claimed PASS. It does not certify semantic correctness, C4 quality, security, renderer output or human approval. Run it last, after regenerating other validation reports.

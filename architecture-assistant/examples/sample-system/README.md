# ParcelFlow sample architecture

This is an illustrative test fixture for a parcel order/label workflow; assumptions are not production advice. Its registries and some older diagrams/module notes remain intentionally small for fast structural regression tests. Do not use a short fixture note as a quality benchmark.

For the expected level of prose depth, read [`00-system-overview.md`](00-system-overview.md), [`01-scope-and-requirements.md`](01-scope-and-requirements.md), [`02-assumptions-and-constraints.md`](02-assumptions-and-constraints.md), [`c2-containers/containers/CNT-API.md`](c2-containers/containers/CNT-API.md), [`data-architecture/data-flows/booking.md`](data-architecture/data-flows/booking.md), and [`functions/specifications/FN-ORDER-001.md`](functions/specifications/FN-ORDER-001.md). These are intentionally explicit about evidence limits, failure modes, open decisions and follow-up ownership; they still do not constitute a real system specification.

Read the registry and [`diagram-plan.md`](diagram-plan.md) for stable IDs and view disposition. Mermaid ID validation does not prove parser/render or visual correctness. From the package root, run `python3 scripts/validate_architecture.py examples/sample-system` for structural checks and `python3 scripts/validate_artifact_depth.py examples/sample-system` for the outline heuristic. The latter is expected to flag the intentionally small legacy fixture notes; see `validation/depth-review-report.md`. The selected expanded documents above demonstrate the intended depth style, but neither a fixture PASS nor a full outline proves semantic correctness.

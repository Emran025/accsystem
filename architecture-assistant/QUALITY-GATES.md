# Quality gates

Gate statuses: `NOT_STARTED`, `IN_PROGRESS`, `BLOCKED`, `PASSED`, `WAIVED`. `WAIVED` requires explicit acceptance by an authorized user/stakeholder and documented scope, rationale, risk and approval reference; an assistant-authored `approved: true` is not approval. `PASSED` means all required checks were actually executed and passed. Unavailable, semantic, visual, security or human checks that were not performed are `NOT_VERIFIED`, never passed.

## Required, distinct checks

| Gate/check | Evidence required | What does not count |
|---|---|---|
| Structural registry | IDs, statuses, parent/child, operation/function, decision, interface references, safe paths; validator command/version/output | A file existing or a diagram looking plausible |
| Inventory and scope | Reconcile source inventory, requirements, known systems/containers/data stores/operations/interfaces and their IDs; name missing/unresolved items | A representative slice, percentage, or statused registry row |
| Cross-artifact consistency | Maintain `validation/architecture-consistency-ledger.md`; compare requirement ↔ assumption ↔ ADR ↔ issue ↔ API/event ↔ diagram ↔ deployment; resolve phase/scope variants explicitly; record both sides, evidence, impact and affected IDs/files | Separate documents that are internally readable but disagree; choosing the newest generated file as truth |
| Artifact depth | Apply each artifact-family checklist in `OUTPUT-DEPTH-AND-AMPLIFIER.md`; ensure applicable sections address behavior, boundaries, tradeoffs, risks, data/security/operations and verification or name the unknown/owner/action | Titles, one-paragraph summaries, technology lists, generic assurances, placeholder text or template headings without analysis |
| Decomposition and disposition | Every C2/C3/C4 candidate has an evidenced selection/disposition; selected scope is enumerated; deferred/not-selected records carry reason, residual risk, owner/assignment action, next step and revisit trigger | Counting an exception/deferred item as completed analysis |
| Decision and authority | ADR alternatives, evidence, consequences, confidence, affected IDs, reversibility and acceptance status; explicit user authority for true gate waivers | Assistant self-approval or `accepted_by` text with no verifiable authority/reference |
| Traceability | Parent-child, operations-functions, decisions-elements, providers-consumers, requirements-artifacts and diagram IDs in both directions | ID existence without meaningful semantic relation |
| Diagram coverage | `validation/diagram-coverage-matrix.md` accounts for every in-scope ID in applicable C1/C2/selected C3/C4/dynamic/deployment/concern views, or records explicit disposition; large diagrams have indexed partitions and cross-links; `validate_consistency_artifacts.py` finds no missing ID rows or missing referenced local diagram files | Diagram count alone; an unindexed split; silently omitting a unit |
| Diagram quality | Viewpoint/scope/legend/labels/ID checks; parser/syntax; render; visual review as separate evidence; diagram level is appropriate to C1/C2/C3/C4 | ID validation described as render/visual/semantic validation |
| Iterative polish | `validation/consistency-review-report.md` records compare→repair→reread→recheck passes; every changed file and impacted dependent is reopened from disk; rerun checks; continue until a full pass yields no new material finding or checkpoint remaining findings as PARTIAL/BLOCKED | Trusting drafting memory; fixing one side only; stopping immediately after a write; relabeling unresolved issues as PASS |
| Operational readiness | Data lifecycle/recovery; threat/security/privacy; reliability/failure; SLO/workload/capacity; deployment/rollback/observability/ownership; tests | Unqualified claims such as “secure”, “scalable” or “production ready” |
| Final release | Final-stage amplifier; actual tools/versions/times/outputs; reconciled ledger, diagram matrix, consistency report, manifest, checkpoint and validation reports; no unresolved blocker/major contradiction in claimed scope; changed files reread after the last repairs | Aggregate score, passing structural fixture, one-way review, or generated documents alone |

C1/context and C2/container are baseline views for every focal system. C3/C4/supporting views are evidence-selected; non-selection can pass only when rationale, uncovered risk, owner/action and revisit trigger are explicit. Missing or conflicting critical requirements keep the affected gate `BLOCKED` or `IN_PROGRESS`; independent safe work continues.

## Reporting contract

Run `scripts/validate_architecture.py` for structural checks, `scripts/validate_artifact_depth.py` for registered C2/C3/C4/function/interface/decision outline coverage, and `scripts/validate_consistency_artifacts.py` to check required ledgers/reports and a row for each in-scope registry ID in the diagram matrix. The depth/consistency-artifact checkers are structural heuristics, not semantic-quality judges. Repair or explicitly disposition every finding, then manually apply the full family checklists and the complete fixed-point consistency-polish procedure in `CONSISTENCY-AND-POLISH-POLICY.md`. Generate/reconcile the ledger, diagram-coverage matrix and review report. Run diagram tools separately and name their limits. Report scope, commit/revision or artifact paths, timestamp, command/tool version, result/output evidence for each check. Split reporting into: inventory count; selected deliverables produced; artifacts reviewed; incomplete/deferred; explicit authorized waivers; unresolved/blocked; and not verified. Exceptions and deferred items are not completed deliverables and must not inflate a completion percentage. No single aggregate percentage can override a named blocker.

## Mandatory diagram-artifact gate
Every workflow stage must leave at least one actual saved diagram artifact that reflects its current evidence and level of maturity. A plan, matrix, textual architecture description, Mermaid inventory without a diagram view, or future drawing commitment does not satisfy this gate. The final release must contain the actual scoped C1 and C2 diagrams for each focal system and all evidence-selected C3/C4/supporting diagrams, with an index and navigable partitions when scale requires. Check diagram files against the registry and coverage matrix; reopen changed files after repairs; run parser/syntax, render and visual inspection as separate checks where tools permit. If any selected view is missing, stale, or not checked, keep the affected gate IN_PROGRESS/BLOCKED or mark the unavailable check NOT_VERIFIED. C3, C4, dynamic, deployment and landscape remain evidence/applicability-selected according to C4 guidance; a defensible NOT_SELECTED disposition is not permission to omit a required C1/C2 baseline or the stage's actual diagram artifact.

## Final report consistency audit
Before release, run `scripts/validate_release_status.py <architecture_dir>` after the structural, depth, traceability and consistency-artifact validators. Its purpose is narrow: compare manifest stage states, the Gate 7 row, open BLOCKER/MAJOR findings in validation reports, blocked depth/consistency checks and required release records. It is not a semantic architecture validator. A structurally consistent `BLOCKED` release is a truthful audit result, not a failed audit. A Gate 7 `PASSED` with any blocker, incomplete required stage, missing ledger/matrix/review report, or inconsistent manifest must be rejected. Save and reread the audit report; if any validation report is regenerated, rerun the audit. Tests must include negative fixtures that deliberately create false PASS and manifest drift.
